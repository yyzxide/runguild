# 2026-09-16 完成门禁与集成验证修复

## 验收证据

`hasMissingTaskEvidence` 统一 Runtime 完成与 Task 解锁的条件：无 Worktree 的执行证据必须属于当前 attempt；代码任务的测试必须对应当前提交和已记录的 tree hash，且执行前后 clean/stable。需要评审的任务只使用当前 attempt 的提交证据集合。相同命令的后续失败会阻止旧通过结果满足验收。

同一 Run 的测试不再绕过提交绑定。测试内容摘要包含执行身份与代码快照，避免不同版本输出相同文本时被去重成旧结果。无修改任务仍不制造空提交，但记录真实基线的提交和 tree 证据。

Agent 交付顺序更新为：修改 -> commit -> 对干净提交执行 test.run -> 创建交付版本与提交评审。再次修改后必须重新 commit 和测试。原有测试断言是否充分覆盖业务需求仍属于独立验收设计问题，本轮不会把“进程退出 0”解释为完整需求正确性。

## 集成验证

每次集成先在 token 隔离的临时 Worktree 构造候选结果，执行准备命令和配置的验证命令。测试失败、候选代码被修改、租约/审批失效、目标分支在验证期间变化，均不发布候选。通过后对检查过的目标 ref 更新：未检出分支使用旧 SHA 条件更新，已检出目标分支只允许干净工作区 fast-forward。

配置复用 `AGENT_TEST_COMMANDS_JSON` 与 `AGENT_WORKTREE_SETUP_COMMANDS_JSON`；临时工作区不会继承 Builder 的 node_modules 等未跟踪文件，需用准备命令安装依赖。验证命令为空时拒绝集成。命令超时由 `INTEGRATION_TEST_TIMEOUT_MS` 控制（默认 120000 ms），总验证同时受租约预算限制；Integration Worker 的默认租约为 900 秒。租约预算不够会失败并保留原分支，不跳过测试。

集成期间仍使用受信任宿主环境执行配置命令，不构成 OS 沙箱。Git 元数据不能保证代码语义正确，保证范围取决于配置的验证命令及其断言。进程在 Git 更新成功但数据库标记前中断，可在后续重试中识别包含已审查提交的目标并重新验证。
